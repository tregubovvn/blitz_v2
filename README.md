# Блиц-опрос (Blitz Quiz)

Учебное приложение «преподаватель — студенты» без серверного кода:

- **Интерфейс** — статические HTML/JS-страницы. Публикуются на **nginx** (http://194.87.103.77/blitz/),
  а для отладки — на **GitHub Pages** (адрес API определяется автоматически, см. `js/common.js`).
- **Обмен данными** — JSON-файлы на вашем сервере **http://194.87.103.77/blitz** через обычный nginx:
  чтение — `GET`, запись — `PUT`, удаление — `DELETE` (простые WebDAV-возможности nginx), списки файлов — `autoindex`.

## Правила теста

1. **Первая страница сайта (index.html) — вход только для студентов.** Панель преподавателя
   открывается только по прямой ссылке **http://194.87.103.77/blitz/teacher.html**.
2. Преподаватель **не пишет вопрос** — он выбирает только **тип** раунда:
   - «варианты» **1.А, 2.Б, 3.В, 4.Г, 5.Д** — на ответ **20 секунд**;
   - «текст» — на ответ **40 секунд**.
3. У каждого студента свой **обратный отсчёт**, который стартует, когда студент *увидел* вопрос.
   Точная синхронизация часов не нужна: учитывается **время, которое каждый затратил** на ответ.
4. Ответы студентов приходят преподавателю и **группируются**: по варианту — точно, по тексту — с учётом
   опечаток. Текстовые ответы приводятся к нижнему регистру; близкие ответы **объединяются в одну
   группу** по расстоянию **Дамерау—Левенштейна**, нормированному по длине слова, с порогом схожести
   **0.80** (нормированное расстояние ≤ 0.20). Преподаватель отмечает **один правильный** ответ
   или нажимает **«Нет правильного ответа»** (доступна в любом режиме — и в вариантах, и в тексте).
5. **Студент не может войти в комнату, которую преподаватель ещё не создал** — при входе код
   проверяется: несуществующая комната и завершённый тест дают понятное сообщение об ошибке.
6. **Кнопка «Пропустить вопрос»** — студент может сознательно пропустить вопрос за −3 очка;
   серия при этом сохраняется.
7. **Кнопки «Следующий раунд» нет**: после выбора правильного ответа очки пересчитываются
   (анимация ~5 секунд в панели преподавателя), затем все автоматически возвращаются в режим
   ожидания следующего вопроса.
8. **Каждая комната работает только на один тест.** После завершения результаты всех студентов
   автоматически сохраняются в **статистику** на первой странице преподавателя: дата, название темы
   (поле в панели комнаты, по умолчанию «Тестирование студентов») и результаты каждого студента.
   Затем **комната удаляется** — войти в неё снова нельзя, пока преподаватель не создаст её заново
   (кнопка «Новая комната (новый тест)» или создание с тем же кодом).
9. Студентов можно **удалять** нажатием на их чип в панели комнаты и кнопкой
   **«Удалить всех студентов»**.
10. **Таблица результатов видна у преподавателя всегда**: между раундами, в панели раунда
    и в финальном экране (полная итоговая таблица + CSV).

### Очки за вопрос (актуальные правила)

- **Верный ответ: S = 10 · M(n) + B**, где **n** — длина серии **включая текущий** верный ответ:
  - множитель серии: n ≤ 3 → **M = 1**; 4 ≤ n ≤ 6 → **M = 2**; n ≥ 7 → **M = 3**;
  - **бонус за скорость B: от +4 до +8** по доле оставшегося времени (мгновенный ответ — +8,
    ответ в последнюю секунду — +4).
- **Неверный ответ: S = −7**, серия сбрасывается (n = 0).
- **Пропуск (кнопка «Пропустить вопрос»): S = −3**, серия **сохраняется**.
- **Таймаут / нет ответа: S = −3**, серия сбрасывается.
- Очки могут быть отрицательными — «отвечать наугад» невыгодно. Пропущенный раунд добавляет
  ко времени штраф (длительность раунда + 5 с).
- Итоговый **балл = 70% за набранные очки (относительно максимума) + 30% за скорость**
  (меньше суммарное время — лучше).
- Группы по месту в рейтинге: **50% лучших — «Отлично» (Золото), следующие 30% — «Хорошо» (Серебро),
  последние 20% — «Удовлетворительно» (Бронза)**. Группы видны в таблицах, статистике и в CSV.
- Заходить можно **в любой момент, в том числе посреди теста** — студент увидит вопрос и оставшееся время.
- **Вход только с ФИО** — минимум фамилия и имя; у студента всегда видны его ФИО, очки, верно/неверно,
  общее время, текущее место в рейтинге, текущая серия и ФИО трёх лидеров.
- После завершения теста **студент получает свой итоговый балл и место** в общем рейтинге
  (и группу Золото/Серебро/Бронза); студентам полный рейтинг не выводится — только
  **три лучших**, у преподавателя — полная таблица. Итог студента сохраняется у него
  на странице даже после удаления комнаты.

Данные на сервере (создаются автоматически):

```
/var/www/blitz/data/
├── rooms/{КОД}.json              — состояние комнаты (статус, раунд, тип, тема, время старта;
│                                   после завершения — standings, затем файл удаляется)
├── students/{КОД}/{sid}.json     — зарегистрированные студенты (удаляются при завершении)
├── answers/{КОД}/r{N}_{sid}.json — ответы (N — номер раунда, skip: true — намеренный пропуск)
├── results/{КОД}.json            — очки, серия, пропуски, время и итоговые группы
└── stats.json                    — общая статистика завершённых тестов (дата, тема, результаты)
```

## Шаг 1. Настройки сервера 194.87.103.77 (nginx)

### 1.1. Проверить наличие модуля WebDAV

```bash
nginx -V 2>&1 | tr ' ' '\n' | grep dav
```

Должно быть `--with-http_dav_module`. В Ubuntu/Debian он есть в пакетах `nginx-full` и `nginx-core`.
Если строки нет: `sudo apt install nginx-full`.

### 1.2. Создать каталог данных и отдать его nginx

```bash
sudo mkdir -p /var/www/blitz/data
sudo chown -R www-data:www-data /var/www/blitz
```

(`www-data` — пользователь рабочих процессов nginx; проверьте своим: `ps aux | grep nginx`.)

### 1.3. Установить конфиг

Скопируйте `nginx/blitz.conf` из этого архива:

```bash
sudo cp blitz.conf /etc/nginx/conf.d/blitz.conf
sudo nginx -t && sudo systemctl reload nginx
sudo ufw allow 80/tcp   # если включён брандмауэр ufw
```

Если на сервере уже есть свой `server{}` для 194.87.103.77 — не добавляйте второй `server`,
а перенесите два блока `location` (из `blitz.conf`) внутрь существующего.

### 1.4. Что делает конфиг (кратко — какие настройки нужны)

| Настройка | Зачем |
|---|---|
| `location /blitz/` + `root /var/www` | путь обмена http://194.87.103.77/blitz → каталог /var/www/blitz |
| `dav_methods PUT DELETE MKCOL;` | браузер сам записывает JSON-файлы (PUT) — серверный код не нужен |
| `create_full_put_path on;` | nginx сам создаёт недостающие подкаталоги (rooms/, answers/…) |
| `dav_access user:rw group:rw all:r;` | права 664 на записанные файлы |
| `autoindex on;` | GET каталога отдаёт список файлов — учитель опрашивает ответы студентов |
| `add_header Access-Control-Allow-Origin "*"` (+ Methods/Headers) | CORS: страница с GitHub Pages может обращаться к серверу |
| `if ($request_method = OPTIONS) { return 204; … }` | ответ на CORS-preflight |
| `Access-Control-Expose-Headers "Date, …"` | JS читает заголовок Date — определение смещения часов |
| `add_header Cache-Control "no-store" always;` | браузер не кэширует состояние/ответы |
| `client_max_body_size 2m;` | защита от крупных загрузок |

(Необязательно) защита записи паролем для `rooms/` и `results/` — закомментированный блок
в конце `blitz.conf`; пароль затем указывается в поле «Пароль учителя» на странице преподавателя:

```bash
sudo htpasswd -bc /etc/nginx/blitz.htpasswd teacher ПАРОЛЬ
```

### 1.5. Проверка

```bash
curl -X PUT -H 'Content-Type: application/json' -d '{"test":1}' http://194.87.103.77/blitz/data/test/ping.json
curl http://194.87.103.77/blitz/data/test/          # autoindex: должен показать ping.json
curl -X DELETE http://194.87.103.77/blitz/data/test/ping.json
```

## Шаг 2. Публикация на GitHub Pages

1. Создайте репозиторий на GitHub (например, `blitz-quiz`).
2. Загрузите **все файлы, кроме папки `nginx/`** (index.html, teacher.html, student.html, css/, js/, .nojekyll) в корень ветки `main`.
3. Откройте **Settings → Pages → Build and deployment → Source: Deploy from a branch**, Branch: `main` / `(root)` → Save.
4. **ВАЖНО.** В **Settings → Pages** НЕ включайте **Enforce HTTPS**.
   Страницу открывайте по адресу вида:
   `http://ВАШ_ЛОГИН.github.io/blitz-quiz/`
   Иначе браузер заблокирует обращение к `http://194.87.103.77/blitz` как mixed content
   (HTTPS-страница не может делать запросы к HTTP-серверу).
5. Если сервер уже доступен по HTTPS (сертификат) — поменяйте в `js/common.js`
   строку `API_BASE` на `https://…`, включите Enforce HTTPS и пользуйтесь HTTPS-версией.

Адреса страниц:

- преподаватель (только по прямой ссылке): `http://ВАШ_ЛОГИН.github.io/blitz-quiz/teacher.html`
- студенты (первая страница): `http://ВАШ_ЛОГИН.github.io/blitz-quiz/` (можно с кодом: `index.html#КОД`)

Ссылку с кодом комнаты удобнее давать студентам прямо из панели преподавателя (кнопка «Копировать»).

## Шаг 3. Отладка на GitHub, публикация на nginx (основной вариант)

Один и тот же код работает в двух окружениях — переключать ничего не нужно:
`js/common.js` сам определяет, откуда открыта страница, и выбирает адрес API
(`/blitz/data` на своём сервере, полный URL — при отладке с GitHub/localhost).

### 3.1. Репозиторий

1. Создайте репозиторий (например, `blitz-quiz`), загрузите туда **все файлы проекта**
   (включая `nginx/blitz.conf`, `.github/`, `.nojekyll`; каталог `data/` в git не попадает — есть `.gitignore`).
2. Локально удобно править в VS Code; серверные данные при отладке не портят репозиторий.

### 3.2. Отладка — три способа

| Способ | Как | Комментарий |
|---|---|---|
| Локально (быстрее всего) | VS Code + расширение **Live Server** (или `python3 -m http.server 8000`) | API уже отвечает с CORS `*`, поэтому запросы к `http://194.87.103.77/blitz/data` работают даже с `http://127.0.0.1:5500` |
| На GitHub Pages (staging) | push в `main` → через ~1 мин страница на `http://ЛОГИН.github.io/blitz-quiz/` | **Не включайте Enforce HTTPS**, иначе mixed content; данные общие с сервером — используйте отдельный код комнаты для тестов |
| Смотреть состояние данных | `curl http://194.87.103.77/blitz/data/` и подкаталоги (`rooms/`, `answers/…`) | плюс DevTools браузера, вкладка Network |

Очистка тестовых данных между отладочными прогонами:

```bash
ssh root@194.87.103.77 'rm -rf /var/www/blitz/data/{rooms,students,bonuses,answers,results}/* /var/www/blitz/data/stats.json'
```

### 3.3. Публикация на nginx — способ А: git pull на сервере (самый простой)

```bash
# один раз:
sudo apt install git
git clone https://github.com/ЛОГИН/blitz-quiz.git /var/www/blitz
# (для приватного репозитория — deploy key: ssh-keygen на сервере, ключ добавить в Settings -> Deploy keys)

# каждое обновление:
cd /var/www/blitz && sudo -u www-data git pull
```

`data/` в git не хранится, поэтому `git pull` не затрагивает результаты тестов.

### 3.4. Публикация на nginx — способ Б: автопубликация при каждом push (GitHub Actions)

В проекте есть готовый workflow `.github/workflows/deploy.yml`: после каждого push в `main`
он сам копирует файлы на сервер через `rsync` по SSH и проверяет, что сайт открылся.

Разовая настройка:

1. На своём компьютере: `ssh-keygen -t ed25519 -f blitz_deploy`
2. Публичный ключ — на сервер:
   `cat blitz_deploy.pub | ssh root@194.87.103.77 'cat >> ~/.ssh/authorized_keys'`
3. На сервере: `sudo apt install rsync`
4. В GitHub: **Settings → Secrets and variables → Actions → New repository secret**:
   - `DEPLOY_SSH_KEY` — содержимое приватного ключа `blitz_deploy`
   - `DEPLOY_USER` — пользователь сервера (например, `root`)
5. Push в `main` → вкладка **Actions** показывает ход деплоя; в конце curl проверяет `teacher.html`.

Каталог `data/` исключён из rsync (`--exclude 'data/'`), поэтому автопубликация
никогда не удаляет результаты тестов. Ручной запуск — кнопкой **Run workflow**.

### 3.5. Публикация на nginx — способ В: вручную

```bash
rsync -avz --exclude 'nginx/' --exclude '.git*' --exclude 'data/' \
  ./ root@194.87.103.77:/var/www/blitz/
```

или через SFTP/панель хостинга (FileZilla): скопировать index.html, teacher.html,
student.html, css/, js/, .nojekyll в `/var/www/blitz/`.

### 3.6. Итоговый цикл работы

```
правка кода → git push → GitHub Pages обновился (проверка)
                       → Actions выложил то же на nginx (боевой адрес)
                         http://194.87.103.77/blitz/
```

## Как пользоваться

**Преподаватель:** открыть только по прямой ссылке `teacher.html` → на первой странице —
**статистика завершённых тестов** (дата, тема; нажмите на запись — раскроются результаты
всех студентов) и карточка «Создать комнату». В панели комнаты указывается **название темы**
(по умолчанию «Тестирование студентов»), показывается ссылка для студентов, чипы студентов
(нажатие — удалить; есть кнопка «Удалить всех студентов»). Далее кнопкой запускается раунд
«Варианты 1.А–5.Д (20 с)» или «Текст (40 с)». Отдельного экрана раунда нет — раунд открывается
прямо в карточке комнаты: таймер, **только реально поступившие ответы** (тексты с опечатками
объединяются автоматически) и кнопка **«Нет правильного ответа»**, доступная в любом режиме.
Рядом — «Тройка лучших». Затем «Следующий раунд» или «Завершить тест» — результаты
автоматически сохраняются в статистику (плюс выгрузка CSV); комната закрывается,
для нового теста создаётся новая комната.

**Студент:** открыть **первую страницу сайта** (ссылку с кодом даёт преподаватель) →
ввести код и **ФИО** (без ФИО вход невозможен) → на экране ожидания выбрать бонусы
(×2, ×3, «Время» — каждый по одному разу, до показа вопроса) → ждать вопроса →
ответить до конца отсчёта. Серия считается автоматически. Можно зайти посреди теста.
Личная панель всегда показывает очки, верно/неверно, время, место, серию и трёх лидеров.
После последнего раунда полный рейтинг не выводится — студент видит только три лучших
результата (свой результат — в личной панели).

## Неисправности

| Симптом | Причина / решение |
|---|---|
| `nginx -t`: unknown directive "dav_methods" | нет модуля http_dav_module → `sudo apt install nginx-full` |
| 403 Forbidden при GET каталога | права: `chown -R www-data:www-data /var/www/blitz` |
| PUT возвращает 405 | модуль dav не подключён (см. выше) |
| 409 Conflict при PUT | не включён `create_full_put_path on;` или нет прав на каталог |
| В консоли браузера ошибка CORS | не добавлены заголовки `Access-Control-*` (проверьте конфиг, `nginx -t && systemctl reload nginx`) |
| Запросы блокируются, ошибка mixed content | страница открыта по https, а сервер по http → откройте по `http://…github.io/…` и не включайте Enforce HTTPS |
| «Нет связи с сервером» | недоступен 194.87.103.77:80 (проверьте `curl` из шага 1.5, брандмауэр) |
| Данные накапливаются | удалите старое: `rm -rf /var/www/blitz/data/answers/{КОД}` и т.п. |

## Ограничения

Защита данных минимальна: любой, кто знает адрес, может читать и писать JSON
(для учебного сценария это допустимо). Для ограничения записи используйте
блок basic auth в `nginx/blitz.conf`. Храните только имена студентов — персональные
данные в этой схеме публиковать не следует.
